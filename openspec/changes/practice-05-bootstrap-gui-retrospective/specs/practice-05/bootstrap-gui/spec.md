# Bootstrap GUI — retrospective delta

## Purpose

Описать уже согласованную форму Practice 5 для просмотра и подтверждения bootstrap. Это ретроспективная запись существующей фичи, а не новые требования к готовому GUI; ADDED относится только к реестру OpenSpec.

## ADDED Requirements

### Requirement: Single form and defaults
GUI SHALL показывать одну русскоязычную форму с неизменяемым корнем, именем, namespace, стилем, bin/examples, действиями Preview/Apply, операциями и результатом. Начальные имя и namespace пусты, стиль google, bin включён, examples выключен; EditorConfig соответствует стилю без отдельного выбора.

#### Scenario: Initial state
- **WHEN** открыта форма
- **THEN** показаны корень, подписи, defaults, подсказка подстановки имени в пустой namespace и «Предпросмотр ещё не выполнен»; Apply недоступен

### Requirement: Preview rendering
GUI SHALL передавать пять полей формы в `preview(root, settings)` и показывать корень, эффективные настройки и все операции в полученном порядке: действие, файл/каталог, относительный путь и оба пути rename. Длинные списки, пути и сообщения доступны целиком через прокрутку или раскрытие; тип различим без одного лишь цвета.

#### Scenario: Successful demo preview
- **WHEN** запрошен Preview для demo_lib с пустым namespace
- **THEN** показан эффективный namespace demo_lib и весь упорядоченный список, а файлы проекта неизменны

### Requirement: Preview freshness
GUI SHALL разрешать Apply только для актуального успешного непустого Preview. Любое изменение параметра, ошибка Preview и любая попытка Apply лишают прежний Preview возможности запуска; пустой список сопровождается «Нет изменений».

#### Scenario: Edit and restore
- **WHEN** параметр изменён после Preview, даже с последующим возвратом
- **THEN** старый список не обозначен актуальным и требуется новый Preview до запуска

#### Scenario: Empty preview or preview failure
- **WHEN** Preview пуст либо закончился ошибкой
- **THEN** Apply недоступен; показаны соответственно «Нет изменений» либо ошибка, повторный Preview возможен

### Requirement: Explicit confirmation
GUI SHALL запрашивать подтверждение с целевым корнем и предупреждением о файловых изменениях, включая удаления. Отказ и закрытие подтверждения сохраняют ввод и Preview без вызова Apply. Подтверждение вызывает ровно один `apply(preview)` с просмотренным результатом без отдельных настроек.

#### Scenario: Cancel or close
- **WHEN** пользователь отменяет или закрывает подтверждение готового Preview
- **THEN** Apply не вызывается, файлы неизменны, ввод и Preview сохранены

#### Scenario: Confirm
- **WHEN** пользователь подтверждает актуальный непустой Preview
- **THEN** передаётся тот же Preview и повторные действия не создают второго одновременного Apply

### Requirement: Responsive operation states
GUI SHALL оставаться отзывчивым, показывать «Подготовка» во время Preview и «Выполняется» во время Apply, блокируя форму и повторные действия. Закрытие главного окна откладывается до результата; отмена выполняющейся операции и пооперационный прогресс не требуются.

#### Scenario: Busy and close
- **WHEN** во время Preview либо Apply пользователь пытается менять параметры, повторить действие или закрыть окно
- **THEN** параметры и действия заблокированы, события GUI обрабатываются, закрытие ждёт завершения

### Requirement: Result and error recovery
GUI SHALL после завершения разблокировать форму и показать успех со сводкой либо ошибку со stage/message и доступными field/path. Ввод сохраняется; ошибки валидации показаны у соответствующего поля, старые ошибки пересматриваются. Ошибка Apply предупреждает о возможных частичных изменениях и необходимости проверить файлы, без обещания отката или сообщения успеха.

#### Scenario: Invalid input and retry
- **WHEN** Preview возвращает ошибку пустого имени, 123-lib или namespace demo::, затем пользователь исправляет ввод
- **THEN** показаны правило имени либо пример demo::lib у нужного поля, прочие значения сохранены; новый Preview пересматривает ошибки

#### Scenario: Apply completes or fails
- **WHEN** Apply завершён успешно либо с ошибкой
- **THEN** показаны соответственно успех и сводка либо ошибка и предупреждение о частичных изменениях; перед повторным Apply нужен новый Preview

### Requirement: Keyboard access
Основные поля, действия и подтверждение SHALL иметь подписи, видимый фокус и доступ с клавиатуры; Tab следует порядку полей и действий. Enter в поле не применяет изменения без подтверждения; при ошибочном вводе фокус переходит на первое ошибочное поле.

#### Scenario: Keyboard interaction
- **WHEN** пользователь проходит форму через Tab, нажимает Enter в поле либо получает ошибку поля
- **THEN** порядок фокуса соответствует форме, Enter не применяет файлы без подтверждения, ошибка переводит фокус к первому ошибочному полю
