# lib-templater Constitution

## Core Principles

### I. Разделение UI и логики

- GUI должен быть настоящим работающим приложением на PySide6.
- Бизнес-логика должна быть отделена от GUI и тестироваться самостоятельно.

### II. Спецификации до реализации

- Две команды работают в двух независимых чатах Codex.
- Одна команда готовит UI-спецификацию, другая — спецификацию логики.
- Общий контракт согласовывается человеком до написания кода.

### III. Минимальные изменения

- Реализуется одна небольшая фича на основе существующего lib-templater.
- Несвязанный рефакторинг и переписывание проекта целиком запрещены.
- Существующие работающие сценарии должны сохраняться.

### IV. Проверяемый результат

- GUI и логика должны работать вместе.
- Обязательны сквозная проверка основного сценария и проверка ошибки
  или граничного случая.
- Результаты проверок должны быть воспроизводимыми.

## Development Workflow

1. Подготовить независимые UI/Logic-спецификации.
2. Согласовать контракт и принять спецификации до кода.
3. Реализовать фичу.
4. Проверить результат и подготовить демонстрацию.

## Governance

Изменения принципов и согласованного контракта требуют одобрения человека.
