# Общий контракт UI ↔ Logic — Practice 5

**Status**: Согласовано человеком до реализации; отражено в Approved v2 обеих спецификаций.

## Вход и проверка

- `preview(root, settings)` принимает корень текущего шаблона и настройки `project_name`, `namespace`, `codestyle`, `keep_bin`, `keep_examples`. Корень задаёт приложение; в GUI он виден и недоступен для редактирования.
- Logic проверяет параметры. Имя соответствует `[A-Za-z][A-Za-z0-9_]*`; непустой namespace — `[A-Za-z_][A-Za-z0-9_]*(::[A-Za-z_][A-Za-z0-9_]*)*`. Пробелы не удаляются автоматически. Пустой namespace из GUI означает имя проекта.
- Стили: `chromium`, `google`, `llvm`, `microsoft`, `mozilla`, `webkit`. По умолчанию: стиль `google`, `keep_bin=true`, `keep_examples=false`; имя и namespace в форме пустые. EditorConfig всегда соответствует стилю, отдельного параметра нет.

## Preview

- Успех возвращает `root`, эффективные `settings` и упорядоченный список `operations`; файлы и каталоги проекта не изменяются.
- Операция содержит `kind` (`create`, `update`, `rename`, `delete`), `target_kind` (`file`, `directory`), относительный к корню `path` и `new_path` только для `rename`. Для переименования обязательны оба пути. Удаление каталога включает его содержимое без обязательного перечисления вложенных файлов.
- UI показывает все операции в порядке списка, корень и эффективные настройки. Корень вместе с относительными путями позволяет понять полные пути. Пустой список означает «Нет изменений», Apply недоступен.
- Preview описывает изменения текущего состояния шаблона с учётом порядка преобразований bootstrap. Между Preview и Apply предполагается отсутствие внешнего редактирования; защита от сторонних изменений файлов в v1 не требуется.

## Подтверждение и Apply

- UI разрешает Apply только для актуального непустого Preview. Изменение любого параметра или ошибка Preview требует нового Preview.
- UI запрашивает явное подтверждение с корнем и предупреждением об изменениях, включая удаления. При отказе или закрытии подтверждения `apply` не вызывается; ввод и Preview сохраняются.
- После подтверждения UI один раз вызывает `apply(preview)`, передавая полученный результат Preview без отдельной передачи настроек. На время работы форма и повторные действия блокируются, GUI остаётся отзывчивым.
- Apply использует корень и эффективные настройки Preview. На неизменённом шаблоне выполняемые действия соответствуют Preview. После любой попытки Apply требуется новый Preview.
- Успех Apply возвращает краткую сводку. Ошибка прекращает дальнейшее выполнение; возможны частичные изменения. Подробный учёт выполненных операций необязателен.

## Ошибки и границы

- Ошибка содержит `stage` (`validation`, `preview`, `apply`), понятный `message`, необязательные `field` и `path`, когда применимо. UI показывает ошибку у соответствующего поля либо в области результата и сохраняет ввод. Ошибка Apply сопровождается сообщением о возможных частичных изменениях.
- Logic работает без PySide6, консольного ввода и завершения вызывающего приложения. Типы операций описывают Preview; Apply использует существующие преобразования `tools/bootstrap.py`, универсальный файловый движок не требуется.
- CLI, интерактивные вопросы, JSON и `--dry-run` сохраняют прежнее поведение. Подстановка пустого namespace GUI не меняет правила CLI/JSON; новое подтверждение для CLI не добавляется.
- Объём: одна форма PySide6 → Preview → подтверждение → Apply → результат. Дополнительные экраны, diff содержимого, отмена выполняющейся операции, транзакции и откаты не входят в v1.

## Приёмка

Обязательны воспроизводимые проверки: успешный сквозной сценарий GUI для `demo_lib`, неверный параметр с понятной ошибкой, отказ от подтверждения без вызова Apply и изменения файлов, самостоятельные проверки Logic и регрессия существующего CLI. Проверки записи выполняются на отдельных копиях шаблона; существующие layout test и `sh scripts/check.sh` сохраняются.
