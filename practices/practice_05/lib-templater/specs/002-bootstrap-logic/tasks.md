## Зависимости и параллельность

Основной порядок: **T001 → US1 (T002–T005) → US2 (T006–T007) → US3 (T008) → GUI US4 (T009–T012) → US5 (T013–T015) → US6 (T016–T017) → проверки (T018–T024) → документация (T025–T026)**.

Внутри каждой истории задачи идут по ID. Начальные тесты должны упасть до добавления соответствующей возможности и пройти на checkpoint. Общие файлы bootstrap/GUI не редактировать параллельно. Поздние проверки продолжают те же истории, не создавая новых функций.

| История | Пример параллельной работы после T017 | Ограничение |
| --- | --- | --- |
| US1 | T018 вместе с T020 и T021 | разные файлы |
| US2 | T019 вместе с T020 и T021 | только после T018: общий logic test |
| US3 | T020 вместе с T018 или T019 и T021 | baseline уже проверен в T001 |
| US4 | T021 вместе с T018 и T020 | GUI-файл занят одной задачей |
| US5 | T022 вместе с T019/T020 | после T021: общий GUI test |
| US6 | T023 вместе с T019/T020 | после T022: общий GUI test |

T024 зависит от T018–T023, T025 — от T024, T026 — от T025. `[P]` отмечает начальные независимые задачи этапа проверок; дальнейшие возможности условны согласно таблице. Все сценарии тестируются на собственных копиях, полный GUI зависит от Logic US1/US2, CLI US3 защищает общие этапы.
