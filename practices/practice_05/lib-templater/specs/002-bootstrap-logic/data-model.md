# Data Model: Bootstrap GUI и Logic

Это проектирование Python-данных по `specs/contract.md`, без хранения, JSON-схемы и изменения общего контракта. Данные и API размещаются в `tools/bootstrap.py`.

## Settings

Небольшая frozen dataclass; входные строки передаются без trim. Defaults формы не заменяют проверку Logic.

| Поле | Тип | Правило / default |
| --- | --- | --- |
| project_name | str | Обязательно; `[A-Za-z][A-Za-z0-9_]*`; форма изначально пуста |
| namespace | str | Пустое из GUI → project_name; иначе `[A-Za-z_][A-Za-z0-9_]*(::[A-Za-z_][A-Za-z0-9_]*)*` |
| codestyle | str | chromium/google/llvm/microsoft/mozilla/webkit; google |
| keep_bin | bool | true |
| keep_examples | bool | false |

Существующие Options остаются внутренними данными CLI/Bootstrapper: editorconfig=`match-codestyle`, dry_run задаётся CLI. Эти два поля в общий Settings не добавляются. Preview хранит эффективные проверенные Settings. JSON по-прежнему разбирается resolve_options; его coercion и правило пустого namespace не меняются.

## Operation

| Поле | Тип | Правило |
| --- | --- | --- |
| kind | str | create/update/rename/delete |
| target_kind | str | file/directory |
| path | str | путь относительно root |
| new_path | str или None | обязателен для rename, отсутствует у остальных |

Операции хранятся в порядке преобразований. Родительский каталог создаётся до файла; rename содержит исходный и конечный пути. Delete каталога включает содержимое. Последовательные update одного пути не сворачиваются. Для UI пути показываются целиком с прокруткой; внутреннее представление допускает `/` независимо от ОС.

## Preview

| Поле | Тип | Правило |
| --- | --- | --- |
| root | pathlib.Path | абсолютный корень текущего шаблона, видимый в GUI |
| settings | Settings | эффективные значения; namespace уже подставлен |
| operations | tuple[Operation, ...] | упорядоченная неизменяемая последовательность |

Preview создаётся только после проверки параметров, обязательной структуры и чтений, необходимых для планирования. Пустой operations — успешный результат «Нет изменений», который UI не разрешает применить. Обязательные файлы: `CMakeLists.txt`, `src/CMakeLists.txt`, `tests/CMakeLists.txt`, `cmake/__PROJECT_NAME__Config.cmake.in`.

Preview не содержит содержимого файлов, diff, идентификатора сессии, токена подтверждения, хешей или блокировок. Небольшие таблицы промежуточного текста/путей принадлежат локальному выполнению Bootstrapper и наружу не возвращаются. Повторная настройка уже переименованного проекта не гарантируется.

## ApplyResult

Frozen dataclass с `summary: str` — непустой краткой сводкой успешного выполнения. Подробный журнал и список завершённых операций не обязательны. При неуспехе ApplyResult не возвращается.

## BootstrapError

Расширение существующего исключения RuntimeError с полями:

| Поле | Тип | Назначение |
| --- | --- | --- |
| stage | str | validation/preview/apply |
| message | str | понятная причина; str(error) возвращает message |
| field | str или None | имя ошибочного параметра, когда применимо |
| path | str или None | связанный путь, когда применимо |

Неверные параметры → validation с field. Отсутствующая структура, ошибки чтения и декодирования при Preview → preview. Отсутствующая структура перечисляется в message; один отсутствующий путь можно также указать в path. Сбой выполнения → apply с path, если доступен. Конфигурационные ошибки CLI доступны как BootstrapError до записи; stage=validation, path указывает JSON, field указывается только для конкретной настройки. argparse сохраняет прежний внешний интерфейс ошибок CLI.

При Apply после первого сбоя следующие действия не выполняются. Данные о частично изменённых файлах могут отсутствовать; UI обязан предупредить об этом. Отказ подтверждения не является сущностью Logic.

## Состояние формы (локальные поля окна)

| Событие / состояние | Хранимый Preview | Доступность и результат |
| --- | --- | --- |
| Начало / изменение поля | отсутствует | Apply недоступен; после изменения нужен новый Preview |
| Подготовка | отсутствует | поля/действия заблокированы, статус «Подготовка» |
| Preview успешен, непустой | текущий объект | Apply доступен, показаны эффективные настройки и все операции |
| Preview успешен, пустой | объект без операций | «Нет изменений», Apply недоступен |
| Preview ошибочен | отсутствует | ввод сохранён, ошибка у field/в результате, доступно исправление |
| Подтверждение | текущий объект | отмена/закрытие диалога возвращает готовый Preview без Apply |
| Подтверждение принято | объект передан worker и исключён из повторного запуска | «Выполняется», форма и действия заблокированы |
| Apply завершён | отсутствует | сводка либо ошибка; форма доступна, повтор требует Preview |

Любой signal изменения параметров делает Preview неактуальным, даже при возврате исходного значения. Во время работы закрытие запоминается и выполняется после finished. UI не хранит постоянную историю и не обещает rollback.
