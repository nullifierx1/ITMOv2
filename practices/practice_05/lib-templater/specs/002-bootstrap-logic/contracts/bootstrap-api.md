# Python binding и пользовательские интерфейсы

Источник требований — согласованный `specs/contract.md`. Этот документ уточняет его реализацию в Python, не заменяет и не расширяет контракт.

## Независимый API: tools/bootstrap.py

| Вызов | Успех | Ошибка |
| --- | --- | --- |
| `preview(root: Path, settings: Settings) -> Preview` | root, эффективные settings, ordered operations | BootstrapError с данными |
| `apply(preview: Preview) -> ApplyResult` | summary | BootstrapError с данными |

Типы и ограничения описаны в `specs/002-bootstrap-logic/data-model.md`. Исключение вместо envelope — выбранный Python binding: GUI и тесты читают поля, CLI может продолжать печатать str(error).

API не импортирует PySide6, не спрашивает ввод, не печатает обязательный результат и не завершает приложение. Settings содержит ровно project_name, namespace, codestyle, keep_bin, keep_examples. EditorConfig следует стилю. Пустой namespace нормализуется только в новом API, без изменения CLI/JSON.

### Preview

1. Проверить параметры с прежними regex, без trim и новых ограничений C++ keywords.
2. Проверить обязательную структуру; перечислить отсутствующее до записи.
3. Пройти существующие преобразования, учитывая промежуточный текст/пути только в памяти.
4. Вернуть операции в порядке действий. Тип create/update определяется перед соответствующим действием. rename имеет оба пути, delete каталога включает содержимое.

Ошибки полей: stage=validation и field; структура/чтение/декодирование: stage=preview, path по возможности. Ни успех Preview, ни его ошибка не меняют файлы/каталоги проекта.

### Apply

UI передаёт сам полученный Preview, без отдельных настроек. Apply использует root/settings, выполняет преобразования bootstrap и возвращает summary; operations не исполняются универсальным движком. При первой ошибке дальнейшее выполнение прекращается, stage=apply. Частичные изменения допустимы, rollback и автоматический retry отсутствуют.

Актуальность, непустота Preview и подтверждение обеспечиваются UI. В Logic не добавляются подтверждение, одноразовые токены, состояние UI или глобальный реестр применений. Предполагается отсутствие внешних изменений шаблона между вызовами.

## GUI: tools/bootstrap_gui.py

Запуск: `python tools/bootstrap_gui.py`; root определяется относительно приложения тем же способом, что существующий bootstrap. Выбор другого root пользователем не добавляется. Для тестов окно создаётся с root отдельной копии, без нового CLI-флага приложения.

- Начальное состояние: пустые имя/namespace, google, bin=true, examples=false; root виден, EditorConfig — «Соответствует выбранному стилю», «Предпросмотр ещё не выполнен», Apply недоступен.
- Preview показывает root, эффективные настройки, все операции с типом file/directory и обоими путями rename; доступны прокрутка и длинные сообщения.
- Любое изменение поля или ошибка Preview требует нового Preview. Пустой список → «Нет изменений», без Apply.
- Подтверждение показывает root и предупреждение об изменениях/удалениях. Отмена и закрытие диалога сохраняют ввод/Preview без вызова Apply.
- Подтверждение принято → один `apply(preview)` в worker; повторные действия и изменение параметров заблокированы, GUI принимает события. После любой попытки Apply нужен новый Preview.
- Успех показывает summary; ошибка показывает stage/message и доступные field/path. Ввод сохраняется, ошибка Apply предупреждает о частичных изменениях и проверке файлов.
- Tab, подписи и видимый фокус обязательны; Enter в поле не запускает применение. Ошибка поля переводит фокус в него. Закрытие во время работы откладывается до finished.

## Существующий CLI

Запуск и флаги сохраняются: `python tools/bootstrap.py [project_name]`, `--namespace`, `--codestyle`, `--editorconfig`, `--keep-bin`, `--no-bin`, `--keep-examples`, `--no-examples`, `--config`, `--dry-run`.

Сохранить вопросы и defaults resolve_options, существующие exit codes, stdout/stderr и отсутствие нового подтверждения. Не направлять legacy dry-run через новый Preview: прежний режим остаётся без записи и с прежним представлением действий.

JSON остаётся объектом: непустой явный строковый аргумент приоритетнее конфигурации; отсутствующие настройки спрашиваются. Отсутствующий namespace вызывает вопрос с предложенным именем, пустой namespace конфигурации ошибочен. Сохраняются str-преобразование имён, bool-преобразование keep_*, неизвестные ключи игнорируются. Явные +/- флаги приоритетнее JSON, противоположные флаги конфликтуют. dry_run берётся из CLI, не JSON. Ошибки конфигурации доступны как исключения, а не только как консольный текст.

## Границы

Нет HTTP API, сериализации Preview, diff, редактора операций, импорта/экспорта GUI, выбора каталога, отмены выполняющейся операции, транзакций или новых исправлений генератора. Проверки интерфейсов перечислены в `specs/002-bootstrap-logic/quickstart.md`.
