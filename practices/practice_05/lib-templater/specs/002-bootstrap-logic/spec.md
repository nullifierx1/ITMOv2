# Feature Specification: Bootstrap Logic v2

**Feature Branch**: `practice_05` — существующая ветка, без переключения

**Created**: 2026-10-26

**Status**: Draft v2 / согласовано человеком до реализации; редакция документа ожидает приёмки.

**Contract**: [Общий контракт UI ↔ Logic](../contract.md) (`specs/contract.md`). Независимая v1 сохранена в коммите `4a82ff2`.

**Input**: Подготовить существующий bootstrap к подключению небольшого GUI: ввод и проверка параметров, предпросмотр без записи, применение после подтверждения, результаты и ошибки, совместимость и независимая проверка логики.

**SPECIFY_FEATURE_DIRECTORY**: `specs/002-bootstrap-logic`

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Проверить настройки и увидеть изменения (Priority: P1)

Пользователь передаёт настройки и получает список предстоящих действий до изменения проекта.

**Why this priority**: Ошибочные параметры и удаление каталогов должны быть видны заранее.

**Independent Test**: На отдельной копии шаблона получить предпросмотр без GUI; сравнить состав каталогов и содержимое файлов до и после.

**Acceptance Scenarios**:

1. **Given** шаблон, `demo_lib`, namespace `demo::lib`, стиль `google`, отключённые bin/examples, **When** запрошен предпросмотр, **Then** возвращаются итоговые настройки и действия со стилями, заменами, переименованиями и необязательными целями; файлы и каталоги не меняются.
2. **Given** имя `9demo`, namespace `demo:::lib` или неизвестный стиль, **When** запрошен предпросмотр, **Then** возвращается ошибка с параметром и правилом; записи нет.
3. **Given** неизменённый шаблон и настройки, **When** предпросмотр повторён, **Then** он описывает тот же набор действий без записи.

### User Story 2 - Применить после подтверждения (Priority: P1)

Пользователь проверяет предпросмотр и явно подтверждает применение этих настроек к указанному проекту.

**Why this priority**: Изменения и удаления должны выполняться после осознанного подтверждения.

**Independent Test**: Без GUI получить Preview и передать его в Apply на отдельной копии шаблона. Отказ проверяется в сквозном GUI-сценарии как отсутствие вызова Apply.

**Acceptance Scenarios**:

1. **Given** успешный предпросмотр, **When** UI не получил подтверждения или пользователь отказался, **Then** UI не вызывает `apply`, проект не меняется и успешное применение не сообщается.
2. **Given** предпросмотр для `demo_lib` и неизменённый проект, **When** применение подтверждено, **Then** выполняются заявленные действия, существует `include/demo_lib/foo.h`, отсутствует `include/foo.h`, возвращается успех.
3. **Given** параметры формы изменены после предпросмотра, **When** пользователь хочет применить изменения, **Then** UI требует новый Preview и подтверждение; `apply(preview)` не принимает отдельные настройки.
4. **Given** подтверждение и ошибка записи во время выполнения, **When** выполнение останавливается, **Then** результат содержит `stage=apply`, понятный `message` и `path`, когда применимо; UI сообщает о возможных частичных изменениях. Подробный учёт завершённых действий необязателен.

### User Story 3 - Сохранить существующий bootstrap (Priority: P2)

Пользователь продолжает использовать CLI, интерактивные вопросы и JSON-конфигурацию.

**Why this priority**: Подключение GUI не должно ломать работающие сценарии шаблона.

**Independent Test**: На отдельных копиях сравнить результат прежнего CLI-запуска и нового подтверждённого сценария с одинаковыми итоговыми настройками.

**Acceptance Scenarios**:

1. **Given** аргументы из `tests/bootstrap_layout_test.py`, **When** выполнен прежний CLI-запуск, **Then** он успешен и сохраняет ожидаемое расположение заголовка.
2. **Given** конфигурация и явные CLI-аргументы, **When** определяются настройки, **Then** сохраняются приоритеты и проверки FR-002–FR-004.
3. **Given** неполный интерактивный запуск, **When** пользователь принимает предложенные значения, **Then** сохраняются прежние вопросы и значения по умолчанию.
4. **Given** полный набор настроек, **When** логика вызывается независимо, **Then** результат доступен без GUI, запроса консольного ввода и разбора печатного вывода.

### Edge Cases

- Отсутствует обязательный файл шаблона: ошибка структуры до записи с перечнем отсутствующего.
- JSON отсутствует, повреждён или содержит массив вместо объекта: ошибка конфигурации до записи.
- Одновременно заданы противоположные CLI-флаги bin или examples: ошибка конфликта.
- Отключённый bin/examples отсутствует: удаление не требуется; включение создаёт существующие заготовки.
- Отключённый bin/examples существует: предпросмотр явно сообщает удаление каталога вместе с содержимым.
- Уже переименованный проект не обязан поддерживать повторную настройку: отсутствие обязательного шаблонного config-файла даёт ошибку структуры.
- Ошибки чтения, декодирования текста, записи, удаления и переименования сообщаются с соответствующей стадией и путём; при применении возможны частичные изменения.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Логика MUST предоставлять `preview(root, settings)` и `apply(preview)` по [общему контракту](../contract.md), независимо от GUI, без интерактивного ввода и завершения вызывающего приложения. Корень задаёт приложение, GUI передаёт `project_name`, `namespace`, `codestyle`, `keep_bin`, `keep_examples`. Logic отвечает за проверку параметров.
- **FR-002**: Правила параметров MUST соответствовать bootstrap; начальные и конечные пробелы не удаляются автоматически:

  | Параметр | Правило и значение по умолчанию |
  | --- | --- |
  | `project_name` | Обязателен; `[A-Za-z][A-Za-z0-9_]*`, без автоматического исправления. |
  | `namespace` | `[A-Za-z_][A-Za-z0-9_]*(::[A-Za-z_][A-Za-z0-9_]*)*`; пустая строка из GUI означает имя проекта. Правила CLI/JSON сохраняются по FR-003–FR-004. Новая проверка ключевых слов C++ не добавляется. |
  | `codestyle` | `chromium`, `google`, `llvm`, `microsoft`, `mozilla`, `webkit`; по умолчанию `google`. |
  | EditorConfig | Соответствует выбранному стилю; отдельного параметра общего API нет. Прежний CLI-параметр сохраняется. |
  | `keep_bin` | Булево решение, по умолчанию включено. |
  | `keep_examples` | Булево решение, по умолчанию выключено. |

- **FR-003**: CLI MUST сохранять позиционный `project_name`, `--namespace`, `--codestyle`, `--editorconfig`, `--keep-bin`, `--no-bin`, `--keep-examples`, `--no-examples`, `--config`, `--dry-run`. Неполные настройки дополняются прежними интерактивными вопросами. `--dry-run` остаётся режимом без записи. Обычный CLI-запуск не получает нового обязательного подтверждения.
- **FR-004**: JSON MUST оставаться объектом с существующими ключами настроек. Для строк сохраняется текущий выбор непустого явного аргумента, затем конфигурации. Если имя не получено, CLI спрашивает его; отсутствующий namespace ведёт к вопросу с предложенным именем проекта, а пустой namespace из конфигурации не проходит проверку. Сохраняются преобразование конфигурационных имён в строки, преобразование `keep_*` по текущему правилу истинности и игнорирование неизвестных ключей. Явный положительный или отрицательный CLI-флаг bin/examples имеет приоритет над конфигурацией, конфликт противоположных флагов отклоняется. `dry_run` определяется CLI-флагом, не JSON. Ужесточение конфигурационного формата вне v1.
- **FR-005**: До записи MUST проверяться наличие `CMakeLists.txt`, `src/CMakeLists.txt`, `tests/CMakeLists.txt`, `cmake/__PROJECT_NAME__Config.cmake.in`. Ошибка структуры перечисляет отсутствующие относительные пути. Проверка и предпросмотр MUST не создавать, не изменять, не перемещать и не удалять файлы и каталоги проекта.
- **FR-006**: Preview MUST возвращать `root`, эффективные `settings` и упорядоченный список `operations`. Операция содержит `kind` (`create`, `update`, `rename`, `delete`), `target_kind` (`file`, `directory`), относительный `path` и обязательный для `rename` `new_path`. Удаление каталога включает содержимое без обязательного перечисления вложенных файлов. Список MUST учитывать последовательное действие преобразований bootstrap. Типы операций описывают Preview и не требуют универсального файлового движка. Diff и содержимое будущих файлов не требуются.
- **FR-007**: Применение MUST сохранять существующие состав и порядок преобразований: запись `.clang-format` и `.editorconfig`, добавление недостающих `.vscode/` и `.idea/` в `.gitignore`, замены шаблонных обозначений в текущем наборе текстовых файлов с текущими исключениями, обработка `tests/CMakeLists.txt`, переименование config-файла и публичного include-каталога, настройка bin/examples. Сохраняются существующие заготовки, перезаписи и правила CMake-блоков; новые исправления генератора не входят в фичу.
- **FR-008**: `apply(preview)` MUST принимать результат успешного Preview без отдельной передачи настроек и использовать его корень и эффективные настройки через существующие преобразования `tools/bootstrap.py`. UI отвечает за подтверждение, допускает один Apply для актуального непустого Preview, при отказе не вызывает Apply и после любой попытки Apply требует новый Preview. На неизменённом шаблоне действия MUST соответствовать Preview; доступность последующей записи не гарантируется.
- **FR-009**: Успех Apply MUST возвращать краткую сводку. Ошибка MUST содержать `stage` (`validation`, `preview`, `apply`), понятный `message`, необязательные `field` и `path`, когда применимо. Ошибки параметров содержат `field`; ошибки структуры/чтения относятся к `preview`, ошибки выполнения — к `apply`. При ошибке Apply возможны частичные изменения; подробный учёт выполненных операций необязателен. Отказ от подтверждения не является отдельным результатом Logic.
- **FR-010**: При ошибке применения дальнейшие действия MUST прекращаться. Полный откат, атомарность, резервные копии и автоматическое повторение не требуются. Ошибки параметров, структуры и чтения, обнаруженные при предпросмотре, MUST сообщаться до применения. Ошибки конфигурации и файловой системы MUST быть доступны независимо от консольного текста.
- **FR-011**: Проверка параметров, Preview, Apply и ошибки MUST проверяться без установленного GUI-фреймворка и ручного ввода. Сквозные проверки настоящего PySide6 GUI MUST покрывать успешный сценарий `demo_lib`, неверный параметр с понятной ошибкой и отказ от подтверждения без вызова Apply и изменения файлов. Регрессия существующего CLI обязательна. Проверки записи используют отдельные копии шаблона. Существующий bootstrap layout test и `sh scripts/check.sh` MUST сохранять своё назначение и проходить после реализации без исправления несвязанных проблем.

### Key Entities *(include if feature involves data)*

- **Настройки bootstrap**: проверенные значения, определяющие преобразования выбранного шаблона.
- **Предпросмотр**: настройки, целевой корень и описания предполагаемых действий, служащие основанием подтверждения.
- **Результат выполнения**: Preview, успех Apply с краткой сводкой либо ошибка по общему контракту; подробный журнал действий необязателен.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Во всех сценариях предпросмотра, ошибки проверки и отказа число созданных, изменённых, перемещённых и удалённых файлов и каталогов проекта равно нулю.
- **SC-002**: Для каждой из четырёх комбинаций bin/examples на неизменённом шаблоне подтверждённый сценарий выполняет все заявленные действия и даёт то же итоговое дерево и содержимое, что прежний запуск с теми же настройками.
- **SC-003**: Для каждого неверного параметра и каждой категории ошибок из Edge Cases результат позволяет определить причину и место ошибки без разбора консольного вывода; ошибочное применение ни разу не обозначается успешным.
- **SC-004**: Самостоятельные сценарии Logic воспроизводимы без графического приложения; GUI-сценарии и отказ проверяются отдельно по FR-011. Существующие проверка заголовка для `demo_lib`, CLI и smoke test сохраняют успешный результат.

## Assumptions

- Источники: `tools/bootstrap.py`, `tests/bootstrap_layout_test.py`, `tests/CMakeLists.txt`, `tests/foo_ut.cpp`, `scripts/check.sh`, `README.md`, `.specify/memory/constitution.md`. README описывает запуск и include-layout; точные правила параметров определяет bootstrap.
- Цель — однократная подготовка исходного шаблона. Корень задаётся явно для независимых проверок; CLI сохраняет определение корня относительно скрипта. Создание нового проекта в произвольном каталоге не добавляется.
- Preview описывает изменения текущего состояния шаблона. Между Preview и Apply предполагается отсутствие внешнего редактирования файлов; защита от сторонних изменений в v1 не требуется. Обнаруженные ошибки доступа и структуры сообщаются.
- Подтверждение относится к новому сценарию подключения; CLI сохраняет прежний запуск. Известные ограничения генератора не исправляются под видом совместимости.
- Вне объёма: дополнительные экраны, новые параметры и стили, транзакции и откаты, универсальный файловый движок, исправление исходного `BUILD_BIN=ON`, C++20/C++23 и CI. Объём GUI: одна форма → Preview → подтверждение → Apply → результат.
- PySide6 — зависимость GUI, не логики. Общий контракт согласован человеком и указан в [specs/contract.md](../contract.md); эта редакция приводит независимую v1 к принятым решениям. Plan, tasks и реализация не входят в эту работу.
