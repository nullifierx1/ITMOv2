# Практика 8. Интерфейс недельного отчёта GitHub

Этапы взяты из лекции 8: задача, прототип, контекст для агента, реализация и проверка. [Лекция 8](https://github.com/nullifierx1/ITMOv2/blob/main/lections/lection_8_Al%20engineering%20tools.pdf)

## 1. Задача

В практике 7.2 недельная сводка приходила по почте. В этой практике сопровождающий репозитория может сам выбрать неделю и посмотреть сводку в браузере. Сценарий один: выбрать понедельник, нажать «Показать отчёт» и увидеть, сколько Issues и PR создали и закрыли или влили за семь дней. Для созданных Issues выводится разбивка по типам и авторам.

Выбрали тестовый репозиторий `nullifierx1/n8n-code-review-test`, чтобы на демонстрации проверить результат по двум известным неделям. [Тестовый репозиторий](https://github.com/nullifierx1/n8n-code-review-test) · [ТЗ практики](https://github.com/ai-course-avito/ITMOv2/tree/main/practices/practice_08)

## 2. Прототип и выбор дизайна

Первый [HTML-прототип](https://github.com/nullifierx1/n8n-github-weekly-report/blob/main/prototype/report.html) собрали в Codex. Запрос был на один экран с формой и четырьмя карточками. В прототипе можно переключить исходный экран, ввод, загрузку, успех, пустую неделю и ошибку. На узком экране карточки стоят в две колонки.

Для доработки сравнили два шаблона в каталоге v0. Pulse рассчитан на мониторинг инцидентов и развёртываний. В Shadcn Dashboard верхняя панель отделена от ряда карточек с ключевыми числами. Для недельной сводки выбрали второй вариант. Из него адаптировали верхнюю полосу для названия репозитория и ряд равноправных карточек. Сразу под заголовком оставили выбор недели, а разбивки разместили под показателями. [Shadcn Dashboard в v0](https://v0.app/templates/Pf7lw1nypu5) · [Pulse в v0](https://v0.app/templates/3hZwaLtyRbc)

v0 показан на слайде 11 лекции. Здесь его каталог использовали для выбора референса, а редактирование прототипа и перенос в React сделали в Codex. Перед этим на первом проходе по shadcn/ui выделили дельту отдельной меткой рядом с каждым числом. В финальном макете добавили верхнюю панель и проверили, что карточки и разбивки помещаются на мобильном экране.

[Экспорт прототипа в PDF](https://github.com/nullifierx1/n8n-github-weekly-report/blob/main/prototype/weekly-report.pdf) содержит шесть состояний сценария и отдельный мобильный экран. PDF открывается на GitHub. [Интерактивный HTML](https://github.com/nullifierx1/n8n-github-weekly-report/blob/main/prototype/report.html) можно скачать и открыть в браузере. Для обоих форматов используются демонстрационные данные.

## 3. Что передали агенту

Для реализации использовали прототип, [спецификацию формы](https://github.com/nullifierx1/n8n-github-weekly-report/blob/main/spec.md) и описанный там JSON-ответ. Макет задаёт расположение элементов. В спецификации отдельно прописано, что делать при пустой дате, дате посреди недели, задержке, повторном Enter и ошибке сервера.

| Этап | Суть запроса к Codex | Что доработали после первого варианта |
|---|---|---|
| Макет | Собрать отчёт и показать состояния одного сценария. | Вынесли сравнение в отдельные метки на карточках и сохранили его рядом с каждым числом. |
| Интерфейс | Переиспользовать элементы shadcn/ui, подключить запрос по контракту и обработать состояния. | Добавили ошибки рядом с полем и блокировку в обработчике формы на время запроса. |
| Тесты | Проверить, что после отправки виден отчёт, а повтор во время задержки не даёт ещё одного запроса. | Управляем задержкой из теста, проверяем число запросов и делаем снимки после наступления нужного состояния. |

## 4. Реализация

Фронтенд написан на React и TypeScript. Сборка и локальный запуск идут через Vite. Кнопка, поле даты, подпись, карточки и сообщение об ошибке используют компоненты shadcn/ui. Цвета и типографика заданы в [теме Tailwind](https://github.com/nullifierx1/n8n-github-weekly-report/blob/main/src/style.css).

При отправке браузер вызывает `/api/weekly-report?weekStart=…`. Vite проксирует запрос к n8n. [Веб-workflow](https://github.com/nullifierx1/n8n-github-weekly-report/blob/main/n8n/weekly-report-api.json) валидирует дату, получает статистику из GitHub Search API и отдаёт JSON. Для веб-отчёта предусмотрен отдельный Webhook. Расписание и почта относятся к автоматизации 7.2.

Пока ответ ожидается, кнопка выключена и виден статус загрузки. Обработчик формы дополнительно проверяет, есть ли запрос в работе. При ошибке поле сохраняет выбранную дату и форму можно отправить снова. Сценарий проверен с клавиатуры, включая переход к полю и отправку через Enter.

## 5. Проверки по лекции

Playwright запускает Vite и подменяет ответы API. Проверки поведения охватывают ввод, валидацию, загрузку, пустые данные, 500 с повторной попыткой и путь до видимого отчёта. В тесте с задержкой ответ удерживается, пока браузер повторяет отправку. До снятия задержки тест проверяет, что запрос остался один.

В [визуальных тестах](https://github.com/nullifierx1/n8n-github-weekly-report/blob/main/tests/visual.spec.ts) используются четыре снимка приложения:

| Снимок | Размер окна |
|---|---|
| Готовый отчёт | 1000 × 900 |
| Готовый отчёт | 390 × 844 |
| Пустая неделя | 390 × 844 |
| Ошибка загрузки | 390 × 844 |

Размеры, локаль и часовой пояс заданы в Playwright. Ответы фиксированы, анимации при съёмке отключены. Снимки делаются на всю страницу, поэтому в мобильный эталон входят и разбивки ниже первого экрана. Baseline привязан к Chromium в Linux.

На предыдущей итерации временно увеличили заголовок и скрыли текст ошибки. Упал визуальный тест и тест поведения при ошибке. После возврата исходников оба прошли. Этот эксперимент показывает визуальное отличие и то, что проверка поведения ловит исчезнувшее сообщение. ## 6. Запуск для ревью

В репозитории фронтенда один раз выполнить `make setup`, затем `make check`, чтобы собрать приложение и прогнать клиентские тесты. Для демо с n8n настроить `.env.local` по README и выполнить `make run`. [Команды и настройки](https://github.com/nullifierx1/n8n-github-weekly-report#запуск)

## 7. Результаты проверок

- Через GitHub Search API подтвердили 8 созданных Issues, 4 закрытых Issues, 7 созданных PR и 1 влитый PR за неделю 16–22 ноября. За 9–15 ноября получили четыре нуля. [Данные GitHub](https://github.com/nullifierx1/n8n-github-weekly-report/blob/main/evidence/github-data.json)
- Интерфейс проверили через локальную подмену webhook с этими данными. Сняли загрузку, пустой результат и ошибку. [Материалы проверки](https://github.com/nullifierx1/n8n-github-weekly-report/blob/main/evidence/README.md)
- Команда `make check` успешно выполнила сборку и все семь тестов Playwright. Команда `make run` запустила интерфейс, локальный HTTP-сервер вернул 200.
