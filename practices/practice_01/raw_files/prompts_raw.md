# Используемые промты

## **ZERO-SHOT**

Посмотри diff: @practices/practice_01/TRAINING_PR.diff

Кратко перечисли проблемы.

Указывай файл и диапазон строк (например app/api.py:35-38).

## **MASTER-PROMPT**

### 1. Цель и роль

* Цель: провести доказательное ревью учебного PR из `TRAINING_PR.diff`. В `risks` попадают только проблемы, которые подтверждаются самим diff или релевантным правилом из `CASE.md`.

* Роль AI: помощник ревьюера. AI анализирует изменения и предлагает проверки, но не принимает решения за человека.

### 2. Входы и источники

Используй только:

@practices/practice_01/TRAINING_PR.diff
@practices/practice_01/CASE.md

Не обращайся к web и не достраивай отсутствующий контекст проекта по догадкам

**Context Pack:**

* `SEC-1`: перед отправкой данных во внешний LLM из diff нужно удалить токены, пароли и приватные ключи.
* `API-1`: diff длиннее 20 000 символов нужно отклонять с HTTP 413.
* `REL-1`: внешний вызов LLM должен иметь timeout 10 секунд ошибку нужно превращать в контролируемый ответ.
* `OUT-1`: ответ содержит `summary`, массив `risks` и массив `checks`. В `risks` максимум три элемента с полями `file`, `line`, `evidence`, `risk`.
* `SCOPE-1`: сервис только советует. AI не пишет код, не approve и не merge PR, не выполняет действия в GitHub.
* `QA-1`: включай риск только тогда, когда он подтверждён строкой diff или правилом репозитория.

Хороший комментарий привязан к конкретному файлу или строке, показывает доказательство, объясняет риск и предлагает воспроизводимую проверку

### 3. Задача и артефакты

Что сделать:

* кратко описать, что меняется в PR
* выбрать максимум три наиболее существенных риска
* для каждого риска указать файл, строку в новой версии файла, доказательство и правило проекта, если оно применимо
* добавить воспроизводимую проверку для каждого риска
* отдельно перечислить проверки, которые стоит запустить для PR

Что вернуть:

Один структурированный результат ревью. Код и файлы остаются только для чтения

### 4. Формат результата

```text
summary: <1-3 предложения>

risks:

1. file: <путь>
   line: <номер строки в новой версии файла>
   evidence: <конкретная строка/фрагмент diff и/или правило CASE.md>
   risk: <что может пойти не так и почему>
   check: <как воспроизвести или проверить>

2. ...

3. ...

checks:

- <проверка 1>
- <проверка 2>
- ...
```

Максимум три риска

Пиши кратко: не пересказывай diff и не добавляй общие советы без привязки к `evidence`

### 5. Полномочия и запреты

Можно:

* читать `@practices/practice_01/TRAINING_PR.diff`
* применять перечисленные правила из `@practices/practice_01/CASE.md`
* делать выводы на основе этих источников
* предлагать проверки

Нельзя:

* менять код
* запускать shell-, web- или git-действия
* approve или merge PR
* выполнять действия в GitHub
* придумывать требования проекта
* ссылаться на неизвестные сведения о версии Python, инфраструктуре, архитектурных соглашениях или тестах

### 6. Рабочий процесс и остановка

1. Определи, какие файлы и строки изменены в diff
2. Сопоставь изменения с релевантными правилами из Context Pack
3. Для каждого кандидата в риск найди конкретное `evidence`
4. Если доказательства не хватает по `QA-1`, не включай этот пункт в `risks`
5. Оставь максимум три наиболее существенных подтверждённых риска
6. Для каждого риска сформулируй воспроизводимую проверку
7. Перед ответом проверь формат результата и границы `SCOPE-1`

### 7. Проверки и evidence

У каждого `risk` должно быть конкретное доказательство:

* строка из diff
* правило `SEC-1`, `API-1`, `REL-1`, `OUT-1`, `SCOPE-1`, `QA-1`
* или их сочетание.

Без такого доказательства пункт не попадает в `risks`.

Для `evidence` сохрани:

* путь к файлу
* номер строки новой версии
* фрагмент или точное описание изменённой строки
* идентификатор применимого правила.

Для `check` укажи:

* вход или условие проверки
* ожидаемый наблюдаемый результат

Если что-то выглядит подозрительно, но не подтверждается разрешёнными источниками, не превращай это в риск.

### 8. Definition of Done

Ревью закончено, когда:

* есть краткое `summary`
* указано не более трёх рисков
* у каждого риска заполнены `file`, `line`, `evidence`, `risk` и `check`
* каждый риск подтверждён diff или правилом из Context Pack
* перечислены воспроизводимые `checks`
* недоказанные предположения не смешаны с подтверждёнными рисками
* ответ не выходит за роль советующего AI-помощника.
