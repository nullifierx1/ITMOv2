# Few-shot

## Артефакт и цель

Проверялся раздел «Рассмотренные альтернативы» в
[`adr.md`](../../practice_01/adr.md). Его слабость — общие причины выбора без
связки «AS IS-факт → решение TO BE → проверяемое следствие». Few-shot выбран,
чтобы показать модели и достаточный пример с evidence, и плохую общую фразу.

Exact prompt: [`prompts_raw.md`](../raw_files/prompts_raw.md), `FEW-SHOT`.
Raw response: [`responses_raw.md`](../raw_files/responses_raw.md), `FEW-SHOT`.

## Что реально ответила модель

Модель дала таблицу из трёх альтернатив. Она отклонила mutable-доступ и
размещение согласованности в manager, а ответственность `Library` за данные и
индекс приняла; для каждой строки добавила следствие, которое можно проверить.

### Принято

- Good/bad examples помогли: первая строка опирается на реальные `data()` и
  `nameIdx()` из [`library.h`](../../practice_01/example_music_library/library.h).
- Модель не приписала `LibraryManager` реализацию: известны только ссылка на
  `Library` и объявления методов в
  [`library_manager.h`](../../practice_01/example_music_library/library_manager.h).
- Вариант 2 сравнивается с вариантом 3 при уже закрытом mutable-доступе.

### Отклонено

- В качестве AS IS нельзя использовать будущий контракт или тесты manager:
  их нет в текущих заголовках. Это лишь следствие гипотетического TO BE.
- Из `weak_ptr<Track>` не следует поведение очистки или жизненного цикла;
  модель на этом вывод не строила.

### Скорректировано

В третьей строке raw response вместе оказались AS IS-факт о полях `Library` и
TO BE из ADR. В улучшенном тексте ADR они разделены.

## Изменённая версия ADR

Раздел «Рассмотренные альтернативы» реально обновлён в
[`adr_few_shot.md`](../modified_artifacts/adr_few_shot.md). В рамках этого
эксперимента Practice 1 не менялась; результат сохранён в независимой версии
ADR. В нём добавлены AS IS
evidence и проверяемые TO BE-следствия для всех трёх альтернатив:

| Альтернатива | Evidence, решение, следствие |
|---|---|
| Оставить mutable-доступ | **AS IS:** `data()` и `nameIdx()` отдают mutable-ссылки на `data_` и `name_to_idx_`. **Отклонить:** внешний код сохраняет путь раздельно менять связанные структуры. **TO BE-проверка:** публичный API не возвращает такие ссылки. |
| Инварианты в `LibraryManager` | **AS IS:** `Library` владеет состоянием, manager хранит ссылку на неё; реализация неизвестна. **Отклонить:** TO BE помещает базовые инварианты состояния вне владельца. **Следствие:** изменение данных и индекса остаётся ответственностью `Library`. |
| Инварианты в `Library` | **AS IS:** `Library` владеет `data_` и `name_to_idx_`. **Принять:** это совпадает с выбранным ADR направлением. **Следствие:** доменные операции поддерживают индекс без mutable-доступа manager. |

Сверены `library.h`, `library_manager.h`, [`analysis.md`](../../practice_01/analysis.md),
[`context.md`](../../practice_01/context.md) и ADR. Raw response не менялся.
